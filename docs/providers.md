# 실제 프로바이더 연결

서버는 기본적으로 가짜 연결만 등록한다. 실제 연결은 `BABOJUBOT_PROVIDERS=claude,codex,opencode,antigravity pnpm dev`로 추가한다. `claude:work`처럼 쓰면 같은 프로그램의 다른 계정 연결이 되고 제품 폴더도 따로 쓴다. 전역 설정에서 사용할 연결을 선택하고 저장한다. 프로그램 설치와 제품 로그인은 사용자가 한다. 실제 모델 호출은 구독 사용량이나 비용을 쓴다.

| 연결 | 시험한 판 | 실행 방식 | 지침 | 끼워 넣기 |
| --- | --- | --- | --- | --- |
| Claude Code | 2.1.317 | 실행마다 duplex stream-json | 기본 지침에 파일로 append | 살아 있는 입력 큐에 전달 |
| Codex | 0.166.0 | app-server 기본, `BABOJUBOT_CODEX_MODE=exec` 선택 | developerInstructions | app-server 턴 ACK; exec 미지원 |
| OpenCode | 2.2.5 | 실행마다 `serve --stdio`로 HTTP 서버 시작 | 기본 지침 유지, session instructions API 추가 | `delivery: steer` 응답 |
| Antigravity | 1.4.12 | 실행마다 한 입력·한 결과 | 첫 입력 앞에 추가 | 미지원 |

판을 제한하지 않는다. 설치된 프로그램을 그대로 쓰며, 표의 판은 실제 호출로 시험한 기준이다. 프로토콜이 어긋나면 준비 확인이나 실행 시도가 실패로 드러난다. OpenCode 1.x는 서버 방식이 달라 동작하지 않는다.

Linux·macOS·Windows를 지원한다. 실제 호출은 Linux(WSL)에서만 시험했고, macOS·Windows는 CI에서 프로그램 연결·조직 경계 읽기·서버 기동 자동 검사만 돈다. 서버 기동은 두 OS 모두 내장 DB로 확인한다(강제 종료 뒤 남은 DB의 정상 정지 포함). 내장 DB는 `pg_ctl`로 켜므로 Windows 관리자 계정에서도 뜬다. 일반 권한 Windows는 미검증이다. Windows에는 프로세스 그룹이 없어, 프로그램이 스스로 끝난 뒤 남은 자식 프로세스는 찾지 못한다. 취소 때는 프로세스 트리를 끝낸다.

## 설정

연결 이름의 영문·숫자를 대문자로 쓰고 나머지는 `_`로 바꾼다. `claude:work`면 연결 ID는 `claude-work`, 설정 이름은 `BABOJUBOT_CLAUDE_WORK_...`이다.

| 환경 변수 | 뜻 |
| --- | --- |
| `BABOJUBOT_<연결>_COMMAND` | 프로그램 위치. PATH에 없을 때 쓴다 |
| `BABOJUBOT_<연결>_PASS_ENV` | 그 연결에 넘길 환경 변수 이름(쉼표로 구분). API 키·Bedrock·Vertex 같은 다른 로그인에 쓴다 |
| `BABOJUBOT_<연결>_ADDITIONAL_MODELS` | Claude 연결의 모델 목록에 더할 모델. `[{"id":"…","label":"…"}]` 형식의 JSON |

프록시·인증서·언어 변수는 항상 넘긴다. 그 밖의 환경 변수는 적은 것만 넘긴다. 쓰는 줄 모르고 다른 계정으로 과금되지 않게 하기 위해서다.

모델은 목록을 받아 오면 그 목록으로 확인한다. 목록이 비었거나(받아 오지 못한 때 포함) Claude처럼 제품에 담긴 목록을 쓰는 연결은 API에서 다른 모델 ID도 받고, 틀린 모델은 실행 시도의 실패로 드러난다. 받아 온 목록에 이름이 빈 모델이 있으면 ID를 이름으로 보인다. OpenCode에서 모델을 정하지 않으면 무료 모델을 먼저 고르고, 없으면 그 연결이 제공하는 첫 모델을 쓴다. 특정 무료 모델의 지속 제공을 보장하지 않는다.

Claude의 모델 목록은 제품에 담겨 있고(`packages/runtime/src/providers/claude-models.ts`) 새 모델이 나오면 제품 판과 함께 갱신한다. 그 전에 쓰거나 일부 계정만 쓰는 모델은 위 설정으로 더한다. 새 ID는 끝에 붙고, 내장 목록과 같은 ID는 그 자리에서 이름이 바뀐다. 내장 목록의 항목을 빼는 설정은 없다. 형식이 틀리거나 이름이 빈 항목은 경고하고 건너뛴다. 설정을 바꾸면 서버를 다시 시작한다. 예전 에이전트에 저장된 `opus` 같은 별칭은 그대로 동작하고, 고르는 칸에 그 값 그대로 보인다.

OpenCode는 시스템 설정을 끌 방법이 없어, `/etc/opencode`가 있으면 경고하고 함께 읽는다.

## 제품 로그인

기본 제품 폴더는 저장소의 `.babojubot`이고 `BABOJUBOT_HOME`으로 바꾼다. 개인 설정·로그인 파일을 복사하지 않는다. 저장소 루트에서 실행한다.

```bash
pnpm provider:login claude   # codex, opencode, antigravity, claude:work
```

실행 시도와 같은 환경으로 프로그램의 로그인을 띄운다. 로그인은 연결 폴더(`providers/<연결>`)에 하며 모든 조직이 그 로그인을 쓴다(아래 조직별 제품 폴더). Claude는 화면에 나온 토큰을 붙여 넣으면 연결 폴더에 0600으로 저장한다. 토큰은 명령 인수·Git·이슈에 넣지 않는다. 무료 모델 제공자는 OpenCode 로그인 없이 쓸 수 있다.

로그인 여부는 파일 위치를 가정하지 않고 프로그램의 응답으로 판단한다. Claude는 `claude auth status`, Codex는 `codex login status`, Antigravity는 `agy models`를 쓴다. Claude와 Antigravity는 실행 시도도 파일 없이 시작하고, 거절되면 로그인 필요로 알린다.

제품 HOME/XDG와 환경 변수 허용 목록은 개인 설정의 자동 유입을 막는 경계다. 호스트 파일·네트워크 접근은 아래 격리 실행을 켰을 때만 막는다. 사용자 홈·자격 증명·연구 원본은 Git에 추가하지 않는다.

## 조직별 제품 폴더

같은 연결이라도 실행 시도는 조직마다 따로 둔 제품 폴더 `providers/<연결>/organizations/<조직>`을 HOME·설정 폴더로 쓴다. 설정·세션 기록·확장(hook·plugin)은 그 조직 안에만 쌓이므로 한 조직의 에이전트가 써 둔 설정을 다른 조직의 프로그램이 읽어 그 조직의 실행 시도 토큰을 내보낼 수 없다. 격리 실행을 켜든 끄든 같다. 끈 경우에는 에이전트가 이 컴퓨터의 다른 폴더도 열 수 있어 보안 경계가 아니며, 다른 조직의 설정이 실수로 섞이는 것을 막는다.

연결 폴더 `providers/<연결>`은 로그인 원본·준비 확인·모델 목록·프로세스 기록에만 쓰고 컨테이너에 넣지 않는다. 로그인은 연결마다 한 번 하고 모든 조직이 같이 쓴다.

| 연결 | 조직이 로그인을 쓰는 방법 |
| --- | --- |
| Claude | 연결 폴더의 토큰을 실행 시도마다 환경 변수로 넣는다 |
| Codex | 원본은 로그인 전용 폴더 `providers/<연결>/login/auth.json`이고, 연결 폴더와 조직 폴더의 `auth.json`은 그 원본을 가리키는 링크다. Codex는 링크를 따라 원본 자리에서 바꿔 쓴다. 그 자리에 보통 파일이 있으면 가장 최근 로그인으로 보고 원본으로 옮긴다(예전 연결 폴더 로그인 포함). 격리 실행에서는 로그인 전용 폴더도 쓰기로 넣는다. 두 조직이 같은 순간에 로그인을 갱신하면 하나가 실패해 다시 로그인해야 할 수 있다. 링크를 먼저 만들어 본 뒤에 로그인을 옮기므로, 링크를 만들 수 없는 컴퓨터(일반 권한 Windows 등)는 로그인을 연결 폴더에 그대로 두고 경고한 뒤 연결 폴더로 돈다(격리 실행은 실패). 여러 조직이 한꺼번에 시작해도 로그인 옮기기는 하나씩 한다 |
| OpenCode | 로그인과 세션이 한 DB에 있어 로그인만 공유할 수 없다. 조직 폴더에 로그인이 하나도 없으면 실행 시도 시작 때 연결의 로그인 목록을 옮겨 넣는다(`auth import`와 같은 규칙, 같은 ID는 건너뜀, 세션은 옮기지 않음). API 키 로그인은 그대로 쓸 수 있고, 갱신되는 계정 로그인은 복사본끼리 어긋나 그 조직에서 다시 로그인이 필요할 수 있다 |
| Antigravity | 로그인 저장 방식이 공개되지 않았다. 조직 폴더로 돌며, 연결 폴더 로그인이 조직 실행에서 보이는지는 실제 로그인으로 확인한다(미확인) |

이 배치 전의 세션 기록은 연결 폴더에 남고 조직 폴더로 옮기지 않는다. 네 연결 모두 이전 세션을 찾지 못하면 새 세션으로 시작한다. 근거와 선택지는 [조사](research/org-product-folders-references.md)에 있다.

## 격리 실행

전역 설정의 `격리 실행` 스위치(기본 꺼짐)를 켜면 실제 연결의 실행 시도와 Claude 미리 압축을 실행 시도마다 Docker 컨테이너 하나에서 돌린다. 꺼져 있으면 지금처럼 이 컴퓨터에서 돈다. 스위치는 누르면 바로 저장되고 다음 실행 시도부터 따른다. 이미 돌고 있는 실행 시도는 그대로 끝낸다. 가짜 연결은 프로그램을 띄우지 않으므로 상관없다.

- 컨테이너: 서버를 띄운 사용자의 uid:gid, 권한(capability) 모두 제거, `no-new-privileges`, 호스트 네트워크 대신 전용 bridge 네트워크(기본 `babojubot`, 컨테이너끼리는 닿지 않음). 같은 이름의 네트워크가 이미 있으면 bridge이고 컨테이너끼리 닿지 않는 설정(`enable_icc=false`)인지 확인하고, 아니면 `격리 환경 없음`이다(`docker network rm`으로 지우면 다음 확인 때 다시 만든다). 이미지는 받아 오지 않는다(`--pull never`).
- 폴더: 같은 경로로 조직 폴더(`shared`) 읽기·쓰기, 자기 개인 폴더 읽기·쓰기, 같은 조직 동료 개인 폴더 읽기만, 그 조직의 제품 폴더(`providers/<연결>/organizations/<조직>`) 읽기·쓰기만 넣는다. Codex는 연결의 로그인 전용 폴더도 읽기·쓰기로 넣는다. 연결 폴더·다른 조직·서버 데이터·사용자 홈·Docker socket은 넣지 않는다.
- 환경: 제품 폴더 환경과 로그인 값은 이름만 명령에 적고 값은 docker 프로그램의 환경으로 넘긴다. GitHub 토큰(`GH_TOKEN`·`GITHUB_TOKEN` 등)·이 컴퓨터의 `PATH`·임시 폴더는 넘기지 않는다. 컨테이너에는 GitHub 로그인이 없다.
- 조직 도구: 사용자 API와 다른 전용 listener를 전용 네트워크의 gateway 주소에 열고 조직 도구 경로만 둔다. 사용자 API와 DB는 loopback에 그대로 둔다. OpenCode는 컨테이너 안 서버를 이 컴퓨터의 loopback에만 공개한 포트와 실행마다 만든 비밀번호로 제어한다.
- 안전 확인: 스위치를 켰을 때·서버 시작·전역 설정 화면·`다시 확인` 때 실행 시도와 같은 네트워크·권한의 시험 컨테이너로 사용자 API·DB 포트(gateway, `host.docker.internal`, 이 컴퓨터의 주소)에 TCP로 닿지 않는지, 전용 listener에는 닿는지 본다. 닿으면 실제 연결은 모두 `준비안됨`(`격리 경계 열림`), Docker·이미지·네트워크를 확인하지 못하거나 확인이 60초 안에 끝나지 않으면 `준비안됨`(`격리 환경 없음`)이다. 연결의 준비 확인 시한(30초)은 이 확인 뒤의 연결 확인에만 쓴다. 확인을 통과하지 않으면 실행 시도는 컨테이너에서도 이 컴퓨터에서도 시작하지 않고 실패로 끝난다. 이 컴퓨터로 대신 돌리지 않는다.
- 정리: 취소 공통 순서(프로토콜 중단 → 2초 → TERM → 2초 → KILL) 뒤 마지막에 컨테이너를 지우고 없어졌는지 확인한다. 지우지 못하면 서버 기록에 남기고, 서버 시작 때 이 제품 폴더가 띄운 컨테이너(`babojubot.owner` label)만 지운다.
- 추가 패키지: 에이전트는 조직 폴더의 가상환경(`shared/.venv`)에 설치한다. 이미지의 시작 스크립트가 없으면 만들고 `PATH`에 넣으므로 다음 실행 시도에서도 쓴다.

공통 이미지는 `pnpm runner:build`(`docker/runner`)로 만든다. Node 24, git, Python, 기본 도구와 Claude Code·Codex(npm)·OpenCode 2.x(GitHub 릴리스, 기본 2.2.5, build arg OPENCODE_VERSION)를 담는다. Antigravity CLI는 공개 설치 경로를 정하지 않아 `docker build --build-arg ANTIGRAVITY_INSTALL="<설치 명령>"`으로 넣는다. 설정은 `BABOJUBOT_DOCKER_COMMAND`·`BABOJUBOT_CONTAINER_IMAGE`(기본 `babojubot-runner`)·`BABOJUBOT_CONTAINER_NETWORK`(기본 `babojubot`)이다.

지원 환경은 Linux Docker Engine이다. Docker Desktop·rootless처럼 gateway 주소가 이 컴퓨터에 없거나 이 컴퓨터의 loopback으로 중계하는 환경은 안전 확인에서 `준비안됨`으로 드러나며 이 컴퓨터로 대신 돌리지 않는다. 조직의 제품 폴더는 그 조직에서 같은 연결을 쓰는 에이전트 컨테이너가 함께 읽고 쓴다. 그래서 실행 시도 토큰이 든 파일은 제품 폴더·조직 폴더 밖 실행 시도 전용 폴더에 두고 그 컨테이너에만 읽기로 넣는다. Codex 로그인 전용 폴더는 그 연결의 모든 조직 컨테이너가 함께 쓰므로, 한 조직의 에이전트가 로그인 파일을 다른 계정으로 바꿀 수 있다. 서버가 강제로 끝나면 남은 컨테이너는 다음 시작 때 지운다. 서버를 root로 띄우면 컨테이너도 root uid로 돈다(권한은 모두 뗀다). 준비 확인(로그인 상태)과 모델 목록은 이 컴퓨터의 프로그램으로 한다.

## 세션과 정리

실행 시도마다 별도 프로세스를 만들고 프로토콜 중단(없는 경우 SIGINT) → 2초 → 프로세스 그룹 TERM → 2초 → KILL 순서로 취소한다. 종료 뒤 남은 그룹도 정리하되, 끝나지 않으면 10초 뒤 포기하고 실행 자리를 돌려주되 기록은 남겨 다음 시작 때 다시 본다. 최종 결과를 받았으면 종료 코드와 상관없이 그 결과를 쓰고, 모르는 출력은 건너뛴다. 재시작 때 연결 폴더(`providers/<연결>/processes`)의 기록으로 잔여 프로세스를 정리한다. 기록은 에이전트가 고칠 수 있는 조직 폴더에 두지 않는다. 기록한 시작 시각과 같은 프로세스만 우리 것으로 본다(Linux는 부팅 식별자도 본다). 시작 시각을 남기기 전에 서버가 죽어 기록에 없으면 건드리지 않는다. Windows는 다른 프로그램이 기록을 열어 둔 동안 덮어쓰기를 거절하므로 시작 시각 저장은 약 5초 동안 다시 시도하고, 끝내 실패하면 경고한다. 끝났음을 확인했을 때만 기록을 지우고, 판단할 수 없으면 건드리지 않은 채 기록을 남기고 경고한 뒤 서버는 시작한다. 깨졌거나 이름과 맞지 않는 기록은 어떤 프로세스도 건드리지 않고 지운다.

MCP bearer는 Claude의 임시 0600 파일, Codex·OpenCode의 자식 환경, Antigravity의 작업 폴더 `.agents/mcp_config.json`으로 전달한다. 격리 실행에서는 Antigravity도 토큰이 든 설정을 실행 시도 전용 임시 폴더에 두고 그 컨테이너 안에서만 작업 폴더의 설정 파일 위에 읽기로 넣는다. 작업 폴더에는 토큰 없는 제품 소유 파일이 자리만 잡으며 같은 조직의 다른 컨테이너에는 그것만 보인다. 명령 인수에는 넣지 않는다. Antigravity는 같은 작업 폴더를 파일 생성부터 제거까지 직렬화한다. 제품 소유 표시가 있는 잔여 파일과 임시 파일만 지우며, 표시가 없는 파일은 비어 있어도 건드리지 않고 그 실행 시도를 실패로 끝낸다. 심볼릭 링크도 거부한다. 파일은 하드링크로 한 번에 나타나고 이미 있는 파일을 덮어쓰지 않는다. 하드링크를 지원하지 않는 파일 시스템에서는 이유와 함께 실패한다. 정상 종료·실패·취소·서버 재시작 때 정리한다.

이전 세션으로 시작하지 못하면 프로그램의 문구와 상관없이 새 세션으로 한 번 다시 시도한다. 로그인 거절은 세션 문제로 보지 않는다. 끝나지 못한 실행 시도는 세션을 지우지 않는다. 공개 활동은 일반적인 시작·재개 실패 안내만 담고 원시 모델 출력이나 내부 추론을 전달하지 않는다. 관찰 가능한 연구 결과는 조직 도구로 기록한다.

Claude는 세션의 누적 비용·토큰을 세션 기록(`cost-state` 행)에 저장하고 재개할 때 이어서 센다. 제품은 이 값을 따로 들고 있지 않고, 실행 시도 전에 그 세션 기록의 마지막 값을 읽어 그 실행 시도의 비용을 누적 비용과의 차이로 계산한다. 그래서 압축이나 취소된 실행 시도가 쓴 비용도 다음 실행 시도에 붙지 않는다. 취소됐거나 결과 없이 끝난 실행 시도는 Claude가 끝날 때 새로 남긴 값과의 차이로 토큰·비용을 보이고, 새 값을 남기지 못했으면 `보고 안 됨`이다. 이어 간 세션의 기록을 읽지 못하면 비용을 짐작하지 않고 `보고 안 됨`으로 둔다(토큰은 결과에 있는 값).

## Claude 미리 압축

전역 설정의 기존 저장 버튼으로 기준 토큰(기본 400,000, 50,000–1,000,000)과 TTL 비율(기본 90%, 50–95%)을 함께 저장한다. 제품 transcript에서 읽은 마지막 주 세션 입력 크기·시각과 캐시 생성 TTL(확인할 수 없으면 1시간)로 예약한다. 해당 metadata가 없으면 추측해서 예약하지 않는다.

일반 실행이 시작되면 그 세션의 예약은 취소된다. 압축과 일반 실행은 에이전트 단위로 배타다. 그 에이전트의 어느 세션이든 압축 중이면 다른 작업의 일반 실행도 기다리고, 다른 세션의 압축은 앞선 압축이 끝난 뒤 진행한다. 압축은 화면에서 취소할 수 없으므로 15분을 넘으면 중단한다(실측값이 아니라 여유 있게 잡은 값이다). 압축도 연결의 동시 실행 상한을 점유한다. 일시정지 중에는 허용하지만 중단·완료 조직에는 실행하지 않는다. 재시작 때 TTL 안의 지난 예약은 다시 확인하고, TTL이 지난 예약은 버린다. 이미 전송한 압축의 결과가 불명이면 자동 재전송하지 않는다.

압축은 저장한 모델·지침·작업 폴더로 같은 세션을 재개한다. MCP 목록은 동일하게 제공하되 별도 정비 토큰은 모든 도구 호출을 거부한다. 일반 Run·Event·활동을 만들지 않는다. compact boundary와 성공 결과, 동일 세션 ID가 모두 확인되어야 성공이다. 중단 신호 뒤라도 이미 성공이 확인된 압축의 결과는 저장한다. 실제 캐시 적중·비용 절약은 아직 검증하지 않았다.

## 수동 실제 시험과 재생 검증

실제 호출을 허용할 때만 다음을 직접 실행한다. 각 실행은 60초 후 취소하며, 격리된 임시 조직에서 `get_run_context` 한 번과 `send_message` 한 줄 OK 답장을 요청한다. Claude는 Haiku, OpenCode는 목록의 무료 모델을 쓰며, Codex·Antigravity는 사용자가 현재 계정에서 가장 저렴한 `BABOJUBOT_SMOKE_MODEL`을 지정해야 한다. 모델 자체가 요청을 어떻게 수행할지는 프로바이더 동작에 따른다. 이 스크립트는 CI에서 실행하지 않는다.

```bash
BABOJUBOT_HOME="$product_root" node scripts/provider-smoke.mjs claude --allow-live
# codex, opencode, antigravity도 같은 위치 인수로 선택
# BABOJUBOT_CODEX_MODE=exec 선택; Codex·Antigravity는 BABOJUBOT_SMOKE_MODEL=<가장 저렴한 모델 ID> 지정
```

이 시험은 단건 연결 확인이다. 세션 재개·끼워 넣기·취소·세션 실패·압축까지 돌리는 시험은 같은 조건으로 `node scripts/provider-live.mjs <연결> --allow-live`이고, `--record`를 붙이면 원본을 Git 밖에 남긴다. 현재 자동 검사는 `packages/runtime/test-fixtures`의 **합성** CLI/HTTP/SSE peer를 쓴다. 실제 녹화로 표현하지 않는다. 재생 형식과 정제 기준은 [fixture 안내](../packages/runtime/test-fixtures/README.md)를 따른다.
