# 에이전트 협력은 영속 기록과 깨우기로 한다

에이전트끼리 살아 있는 세션으로 직접 대화하지 않는다. 협력은 조직 ID가 붙은 연구 기록(작업, 메시지, 산출물, 연구 노드)으로만 남기고, 받는 에이전트는 그 기록이 만든 깨우기로 새 실행 시도를 시작한다. 관찰, 조직 경계 강제, 일시정지·재개, 장애 복구가 모두 같은 기록 위에서 해결되기 때문이다. Paperclip이 이 방식이고, Hermes·OpenClaw·Grok Bot은 세션 간 메시지나 그룹 채팅을 쓴다([조사](../research/agent-interaction-models.md)).

## Consequences

- 실시간 대화보다 응답이 느리다. 한 에이전트에 쌓인 깨우기는 하나의 실행 시도로 합친다.
  - 덧붙임(2026-10): 예외 하나. 사용자가 `중단하고 보내기`로 끊고 넣은 메시지가 기다리면 그 실행 시도는 그 메시지만 받고, 나머지 깨우기는 다음 실행 시도가 합쳐 받는다([상호작용 규칙](../architecture.md#상호작용-규칙)).
- 실행 중 주입(steer)은 Lead에게 가는 사용자 메시지에만, 실행기가 지원할 때 쓴다.
