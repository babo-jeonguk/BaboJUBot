# 고정 승인 대신 조직별 승인 정책, 기본은 꺼짐

초기 요구사항은 신규 작업자 추가, 큰 목표 변경, 추가 예산을 항상 사용자 승인 대상으로 두었다. 사용자는 Lead가 기본적으로 자율 운영하고, 사용자가 조직마다 체크박스로 고른 행동만 승인을 거치기를 원했다(2026-10-13). 그래서 초기 연구 승인과 최종 완료만 끌 수 없는 사용자 결정으로 고정하고, 나머지는 기본 꺼진 승인 정책으로 둔다. 강제 수단은 그대로 제품 코드다. 정책이 켜진 행동의 도구 호출을 제품이 승인 요청으로 바꾸며, 정책은 사용자만 바꾼다.

## Consequences

- 새 조직은 승인 없이 작업자 추가, 목표·완료 기준 변경, 추가 예산 요청을 할 수 있는 상태로 시작한다. 예산 한도에 닿을 때의 자동 일시정지는 정책과 무관하게 항상 동작한다.
- "큰 목표 변경"을 Lead가 판단하지 않는다. 목표·완료 기준 기록의 변경 자체가 정책 항목이다.
