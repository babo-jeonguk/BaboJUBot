# 검증

## 실행 시점

- 개발·리뷰 수정 중에는 관련 테스트와 필요한 패키지 타입 검사만 실행합니다. 공용 변경은 호출자까지 포함하며, 영향이 불명확하면 검사 범위를 넓힙니다.
- 로컬 리뷰 수렴 후 커밋 대상·포맷을 확정하고 아래 완료 검사를 실행합니다.

## 완료 검사

| 변경 | 검사 |
| --- | --- |
| 모든 변경 | `git diff --check`, `pnpm check` |
| 제품 코드 | `pnpm test`, `pnpm typecheck`, `pnpm lint` |
| 빌드·실행 환경 | `pnpm build`, 관련 실행 확인 |
| 브라우저 동작 | 관련 E2E, 실제 화면·조작 확인 |

해당 행을 모두 적용합니다. 조직 상태·승인·조직 분리 계약을 바꾸면 해당 핵심 시나리오도 검증합니다. 실패는 원인을 확인해 해소합니다.

## 결과 재사용

- 검사별 대상 SHA·미커밋 변경·명령 또는 CI run·결과를 기록하고, 실패 출력·종료 코드와 미검증 범위를 남깁니다.
- 성공한 결과는 이후 diff와 환경을 확인해 재사용합니다. 코드·테스트·의존성·설정·환경의 영향이 있거나 불명확하면 해당 검사를 다시 실행합니다.
- PR에 검증 근거와 재사용 이유를 모읍니다. 로컬 재사용과 별개로 PR·main의 CI는 실행하며, 병합은 [병합 절차](pr-merge.md)를 따릅니다.
