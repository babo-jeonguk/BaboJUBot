# 검증

언제 어떤 검사를 실행하고 결과를 재사용하는지 다룹니다. 단계별 완료 조건은 각 절차 문서가 정합니다.

## 실행 시점

- 개발·리뷰 수정 중에는 관련 테스트와 필요한 패키지 타입 검사만 실행합니다. 공용 변경은 호출자까지 포함하며, 영향이 불명확하면 검사 범위를 넓힙니다.
- worker가 고친 코드도 parent가 직접 검사합니다. worker의 보고만으로 완료를 판단하지 않습니다.
- 로컬 리뷰 수렴 후 커밋 대상만 있는 환경에서 포맷을 확정하고 아래 완료 검사를 실행합니다.
- E2E는 고정 포트(`3199`/`5199`)를 쓰므로 worktree끼리 동시에 실행하지 않습니다.

## 완료 검사

| 변경 | 검사 |
| --- | --- |
| 모든 변경 | `git diff --check`, `pnpm check` |
| 제품 코드 | `pnpm test`, `pnpm typecheck`, `pnpm lint` |
| 빌드·실행 환경 | `pnpm build`, 관련 실행 확인 |
| 브라우저 동작 | 관련 E2E, 실제 화면·조작 확인 |

해당 행을 모두 적용합니다. 조직 상태·승인·조직 분리 계약을 바꾸면 해당 핵심 시나리오도 검증합니다. 실패는 원인을 확인해 해소합니다.

## 테스트 작성

- 잠든 시간이나 부수적인 횟수 대신 관찰 가능한 상태·준비 줄(handshake)을 기다립니다.
- 신호를 보내기 전에 완전한 stdout 줄을 모으고 exit/error 관찰을 등록합니다.
- 준비와 정리에는 시한을 두고, 정리는 `finally`에서 기다립니다.
- 상속 환경 변수·port·임시 폴더를 분리하고, 실패를 숨기려고 재시도나 단언 약화를 쓰지 않습니다.
- 50번 반복하는 스트레스 검사보다 결정적인 gate 경쟁 하나와 실제 통합 검사 하나를 선호합니다.

## 결과 재사용

- 검사별 대상 SHA·미커밋 변경·명령 또는 CI run·결과를 기록하고, 실패 출력·종료 코드와 미검증 범위를 남깁니다.
- 성공한 결과는 이후 diff와 환경을 확인해 재사용합니다. 코드·테스트·의존성·설정·환경의 영향이 있거나 불명확하면 해당 검사를 다시 실행합니다.
- PR에 검증 근거와 재사용 이유를 모읍니다. 로컬 재사용과 별개로 PR·main의 CI는 실행합니다.
