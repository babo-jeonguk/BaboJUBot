# 리뷰 반영

리뷰 수정·반영 요청에 적용합니다. 리뷰만 요청받으면 결과만 전달합니다.

## 1. 지적 검증

- PR·base/head·리뷰 SHA와 현재 코드를 대조합니다. finding별 고정 ID·Standards/Spec 축·위치·실패 조건·영향·명세/표준 근거를 확인합니다.
- 아래 판정별 근거·다음 처리를 기록합니다. 사용자 결정에 의존하는 변경은 대기하며, 이월만으로 blocker를 해소하지 않습니다.
- 설계 권고는 채택 이유를 판단하고 자동 수정 blocker로 삼지 않습니다. 기계적 반복 문제는 자동 검사로 옮깁니다. 이슈 게시는 [이슈 운영 규칙](issue-tracker.md)을 따릅니다.

| 판정 | 근거 |
| --- | --- |
| 수정 | 재현·수정 SHA·회귀 검사 |
| 반증 | 코드·계약·재현상 성립하지 않는 이유 |
| 의도된 동작 | 요구·확정 결정 링크 |
| 사용자 결정 필요 | 상충 근거·선택지·영향 |
| 후속 처리 | 회귀/기존 결함 구분·이월 이유·이슈·남은 위험 |

**완료:** 모든 finding의 판정·근거·다음 처리와 미해결 blocker가 드러납니다.

## 2. 원인 수정과 실패 유형 검증

- 가능한 경우 수정 전 실패를 재현하고, 같은 원인의 다른 위치·인접 실패 경로까지 확인해 원인 경계에서 고칩니다. 범위는 해당 원인·계약에 한정합니다.
- 회귀 테스트로 수정 전 실패·수정 후 통과를 확인합니다. 제품에 없는 재시도·깨우기를 helper로 추가해 결함을 가리지 않습니다. 재현이 어려우면 한계를 남깁니다.
- 문서와 검증 근거를 [공통 검증 기준](../../README.md#검증-기준)에 맞춰 갱신합니다. 기존 PR은 같은 브랜치에 커밋·push하고 CI를 확인합니다.

**완료:** 원인·같은 실패 유형의 처리 범위와 현재 코드의 검증 근거가 연결됩니다.

## 3. 재검토와 수렴

- 이전 검토 이후 diff와 기존 finding 상태를 먼저 확인합니다. 권한·상태 전이·공유 계약 변경은 호출자까지 추적하고, 전체 재검토가 필요하면 이유를 남깁니다. 같은 지적을 중복 등록하지 않습니다.
- **지적 접수 → 검증·수정 → 재검토 결과 확인**이 1회입니다. 3회에도 수렴하지 않으면 다음 수정 전에 근거·반복 원인·범위·접근을 재점검해 사용자에게 보고합니다. 미해결 blocker는 유지합니다.
- 회차·검토/수정 SHA·finding 상태와 근거를 PR 댓글에 남기고 세션이 바뀌어도 이어갑니다. PR 생성 전에는 로컬 기록을 쓰고, 재검토 후 [구현 3단계](implementation.md#3-로컬-리뷰와-커밋)로 돌아갑니다. PR 생성 시 로컬 기록을 옮깁니다.
- 기존 PR의 외부 리뷰 수정은 아래 자료를 전달하면 인계 완료입니다. 병합은 별도 요청 후 [병합 절차](pr-merge.md)를 따릅니다.

**완료:** 재검토 범위·회차·finding 상태·다음 판단이 추적 가능합니다. 외부 리뷰 대기 시 수정·인계 완료로 보고합니다.

## 외부 리뷰 요청 형식

아래를 실제 값으로 채워 **백틱 5개의 단일 블록**으로 전달합니다. 링크는 고정 SHA·결정 댓글을 쓰고 자격 증명·실제 연구 데이터는 제외합니다.

`````text
mattpocock-skills v1.3.1의 code-review 방식으로 Standards와 Spec을 분리해 검토해 주세요.
https://github.com/mattpocock/skills/blob/v1.3.1/skills/engineering/code-review/SKILL.md
Repository / PR: <주소>
Spec·확정 결정 / 저장소 표준: <링크; 이슈 없는 작업은 승인된 요구를 기재>
Base / Head SHA: <각 SHA>
전체 diff: git diff <base>...<head>
커밋: git log <base>..<head> --oneline
회차 / 이전 검토 SHA·재검토 diff: <N / 첫 리뷰는 이전 값 없음>
수정 전후 동작 / 위험: <내용>
검증: <명령·SHA 또는 CI run·결과> / 미검증 범위: <내용>
기존 finding: <ID·축·판정·수정 SHA/검사 또는 결정/반증 근거> / blocker: <내용 또는 없음>
지적에는 위치·실패 조건·영향·명세/표준 근거를 포함하고 확정 위반과 설계 권고를 구분해 주세요.
재리뷰는 변경 diff·기존 지적을 먼저 확인하고, 권한·상태·공유 계약의 영향 경로와 검토 범위를 밝혀 주세요.
`````
