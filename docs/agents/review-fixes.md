# 리뷰 반영

로컬 또는 외부 코드 리뷰 결과의 수정·반영 요청에 적용합니다.
Standards와 Spec 결과는 별도로 유지하고, finding을 검증한 뒤 코드·테스트·기록을 고칩니다.
리뷰만 요청받은 경우에는 검토 결과를 전달하며, 수정·게시 범위는 사용자의 지시를 따릅니다.

## 1. 지적 검증

- PR identity·base/head SHA와 리뷰 대상 SHA를 확인합니다. 이미 수정된 코드에 대한 지적인지 먼저 대조합니다.
- finding마다 안정적인 ID를 붙이고 축·위치·실패 조건·영향·명세/표준 근거를 기록합니다.
  실제 결함과 가독성·설계 권고를 구분하고, 도구로 판정할 수 있는 반복 문제는 기존 자동 검사를 보강합니다.
- 코드·호출자·확정 결정·재현으로 지적과 반증을 확인하고 다음 판정과 근거를 PR 댓글에 남깁니다.
  PR 생성 전에는 로컬 리뷰 기록에 보존한 뒤 PR 생성 시 옮깁니다.

| 판정 | 필요한 근거와 처리 |
| --- | --- |
| 수정 | 실제 실패 조건·영향, 수정 커밋과 회귀 검증 |
| 반증 | 재현 결과·코드·계약상 문제가 성립하지 않는 이유 |
| 의도된 동작 | 요구사항 또는 사용자 확정 결정 링크 |
| 사용자 결정 필요 | 상충하는 근거·선택지·영향. 결정에 의존하는 변경은 대기 |
| 후속 처리 | 이번 회귀/기존 결함 구분, 이월 이유·관련 이슈·남은 위험. 이번 blocker라면 이월만으로 해소하지 않음 |

권고는 효과와 범위를 판단해 채택 여부를 설명합니다. 자동 수정 루프의 blocker로 취급하지 않습니다.
이슈 게시·변경은 [이슈 운영 규칙](issue-tracker.md)을 따릅니다.

**완료 조건:** 모든 finding에 판정·근거·다음 처리가 있고, 미해결 blocker와 사용자 결정이 드러납니다.

## 2. 원인 수정과 실패 유형 검증

- 결함은 가능한 경우 수정 전 실패를 재현합니다. 자동 재현이 어렵다면 조건·관찰 결과·한계를 남깁니다.
- 같은 원인이 있는 다른 위치와 인접 실패 경로를 확인하고, 원인을 소유한 경계에서 고칩니다.
  예를 들어 DB 종료 결함은 정상 종료·시작 실패·이미 끝난 프로세스·정리 실패의 수명주기 계약을 함께 확인합니다.
  조사 범위는 해당 원인과 계약을 따르며 무관한 리팩터링은 별도 판단합니다.
- 회귀 테스트는 실패 조건과 외부 동작을 검증합니다. helper가 제품에 없는 재시도·깨우기를 추가해 결함을 가리지 않게 합니다.
  가능하면 수정 전 실패·수정 후 통과로 테스트가 결함을 잡는지 확인합니다.
- 변경에 맞는 검사를 실행하고 문서·PR 본문을 갱신합니다. 범위·SHA별 검증은
  [최종 head 검증](pr-merge.md#3-최종-head-검증)을 따릅니다.
- 기존 PR의 수정이면 같은 작업 브랜치에 커밋·push하고 CI를 확인합니다.
  finding별 수정 SHA·회귀 검사·남은 한계를 기록합니다.
  PR 생성 전 로컬 리뷰는 수정·검증 기록을 보존해 아래 재검토를 마친 뒤 [구현의 로컬 리뷰 단계](implementation.md#3-로컬-리뷰와-커밋)로 복귀합니다.
  커밋·push·PR 생성은 그 구현 절차에서 이어갑니다.

**완료 조건:** 결함 원인과 같은 실패 유형의 처리 범위가 설명되고, 수정·검증 근거가 현재 head에 연결됩니다.

## 3. 재검토와 수렴

- 재검토에서는 이전 검토 이후 diff와 기존 finding의 해결 여부를 먼저 확인하고 같은 지적의 중복 등록을 피합니다.
  권한·상태 전이·공유 계약이 바뀌면 호출자와 영향 경로까지 넓혀 검토하고, 전체 재검토가 필요하면 이유를 기록합니다.
- 같은 작업에서 **지적 접수 → 검증·수정 → 재검토 결과 확인**을 한 회로 셉니다.
  세 회에도 수렴하지 않으면 다음 반복 수정 전에 finding 처리 근거·반복 원인·변경 범위·해결 접근을 재점검해 사용자에게 보고합니다.
  커밋 수나 지적 수로 세지 않으며, PR 생성 전 로컬 회차도 PR으로 옮깁니다. 새 세션에서도 기록의 회차를 이어갑니다.
- 미해결 blocker는 유지합니다. 회차 상한은 병합 허용 근거가 아니며, 새 제품 결정이 필요하면 사용자 판단을 받습니다.
- 매회 PR의 리뷰 반영 댓글에 회차·검토 SHA·finding 상태·근거를 갱신합니다. PR 생성 전에는 로컬 기록에 남깁니다.
  기존 PR의 외부 리뷰 수정이면 아래 형식으로 사용자에게 재리뷰 자료를 전달합니다.

**완료 조건:** 재검토 범위·회차·finding 상태가 추적 가능하고, 미해결 사항과 다음 판단이 드러납니다.
외부 리뷰가 남아 있으면 「수정·인계 완료」로 보고합니다. 병합은 사용자 요청 후 [병합 절차](pr-merge.md)를 따릅니다.

## 외부 리뷰 요청 형식

최종 응답에 아래 항목을 실제 값으로 채운 **백틱 다섯 개의 단일 코드 블록**을 제공합니다.
첫 리뷰에는 전체 변경을, 재리뷰에는 이전 검토 SHA 이후 변경과 기존 finding 상태를 명시합니다.
명세·표준·결정은 외부 검토자가 열 수 있는 고정 SHA의 저장소 링크와 이슈 댓글 링크로 전달합니다.
이슈 없는 작업은 승인된 요구사항을 블록에 적습니다. 자격 증명·실제 연구 데이터는 넣지 않습니다.

`````text
mattpocock-skills v1.3.1의 code-review 스킬 방식으로 코드 리뷰해 주세요.
기준: https://github.com/mattpocock/skills/tree/v1.3.1
스킬 원문: https://github.com/mattpocock/skills/blob/v1.3.1/skills/engineering/code-review/SKILL.md
Standards와 Spec 두 축을 분리해 검토하고 결과를 보고해 주세요.

Repository / PR: <주소>
Spec 및 사용자 확정 결정: <링크 또는 승인된 요구사항>
저장소 표준: <AGENTS.md와 관련 문서의 고정 SHA 링크>
Base: <브랜치와 SHA>
Head SHA: <SHA>
최초 검토 범위: git diff <base-SHA>...<head-SHA>
커밋 목록: git log <base-SHA>..<head-SHA> --oneline
이전 검토 SHA / 재검토 diff: <첫 리뷰는 해당 없음; 그 외 이전 SHA와 diff>
현재 회차: <첫 리뷰 또는 수정·재검토 N회>

변경 목적과 수정 전후 동작:
<내용>

검증 근거:
- <검사 명령 / 검증 SHA 또는 CI run / 결과>
- 미검증 범위와 알려진 한계: <내용>

기존 finding과 처리:
- <ID / Standards 또는 Spec / 판정 / 수정 SHA·회귀 검사 또는 결정·반증 링크>
- 미해결 blocker: <내용 또는 없음>

각 지적에는 위치·실패 조건·영향·요구사항 또는 표준 근거를 포함해 주세요.
확정 위반과 코드 스멜에 따른 판단·설계 권고를 구분해 주세요.
재리뷰에서는 이전 검토 이후 변경과 기존 finding의 해결 여부를 먼저 확인해 주세요.
권한·상태 전이·공유 계약 변경은 영향 경로까지 검토하고 검토 범위를 밝혀 주세요.
`````
