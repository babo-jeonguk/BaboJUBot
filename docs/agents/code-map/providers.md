## 연결 경로

공통 순서는 [공통 경로](shared-path.md)를 따릅니다.

```text
전역 설정 → PUT /api/providers/defaults·/:providerId/limit(app, 등록부 확인) → db updateProviderDefaults·updateProviderLimit
  → settings_changed 신호(조직 Event 없음) → 다른 탭 providers 재조회; 상한 변경은 dispatcher.kickProvider
에이전트 상세 → PUT …/agents/:agentId/provider → db updateAgentProvider(조직 → 에이전트 잠금, core planAgentProviderChange)
  → agent.provider_changed → 그 에이전트 kick
claimNextRun(조직 → 에이전트 → 세션 자리 읽기 → lockProviderSlot, core admitsProviderRun·planRunStart가 연결·모델 고정)
  → dispatcher가 run.provider의 adapter 실행(요청 model) → finishRun(조직 → 에이전트 → 실행 시도, 세션 자리에 저장)
  → kickProvider(같은 연결을 기다리는 에이전트), 로그인 필요 실패면 ReadinessMonitor.check
서버 시작·전역 설정 화면·다시 확인 → ReadinessMonitor.check(시작 신호 → 격리를 켰으면 IsolationGate 안전 확인(자기 60초 시한, 닫으면 끝남) → adapter.checkReadiness(30초 시한) → saveProviderReadiness → 끝 신호)
격리 켜짐 → 실행 요청 조립(place: 안전 확인 통과면 execution=container·전용 listener 주소, 아니면 IsolationError로 실패) → adapter가 startProcess({ container })로 docker run → 끝·취소 순서 마지막에 컨테이너 제거
```

상한을 넘었는데 시작한 실행 시도는 `lockProviderSlot`, 기다리는 깨우기가 시작하지 않으면 `kickProvider`·`listAgentsWithPendingWakes`, 다른 탭이 갱신되지 않으면 `settings_changed` 처리에서 시작합니다.
