| 서버 시작/종료·embedded/외부 DB·정적 웹 | [server/main.ts](../../../apps/server/src/main.ts), server/app.ts, [db/client.ts](../../../packages/db/src/client.ts); [시작/종료 테스트](../../../apps/server/test/main.test.ts)(종료 신호는 main.ts만 받아 서버 정리 → DB 닫기 순서로 끝냄, 시작·정리 실패는 1, 정리 시한 BABOJUBOT_SHUTDOWN_TIMEOUT_MS(기본 30초, 잘못된 값이면 시작하지 않음, 감싸는 실행기의 정지 시한은 이보다 길게))·DB 테스트(DB를 열어도 종료 신호를 가로채지 않음)·관련 실행 확인. 내장 Postgres 켜기·끄기·남은 DB 정리는 [db/embedded.ts](../../../packages/db/src/embedded.ts)(묶여 온 pg_ctl), embedded-postgres의 import 종료 hook 제거와 binary 경로 내보내기는 [patches](../../../patches/) |
| 임시 Postgres 수명·테스트 환경(테스트 실행마다 cluster 하나, 테스트마다 migration 끝난 원본 복제) | [db/testing.ts](../../../packages/db/src/testing.ts) `startTestCluster`·`createTestDatabase`, [vitest globalSetup](../../../packages/db/src/test-cluster.ts)(DB·서버 vitest 설정이 씀. 빠지면 `createTestDatabase`가 실패), db/embedded.ts(`startEmbeddedCluster`: pg_ctl로 켜고 `close`로 정상 정지, 프로그램이 정리를 마치지 못하고 끝나면 프로세스 종료 때 자기가 켠 Postgres에만 즉시 정지를 보냄(최대 1.5초, 서버 정리 시한 안, 다음 시작이 복구). dataDir는 한 프로세스만 씀(주인 기록 `<dataDir>.owner.json`을 hard link로 하나만 만듦, 살아 있는 주인이 있으면 시작하지 않음).
