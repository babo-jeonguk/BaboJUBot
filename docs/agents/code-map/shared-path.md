# 공통 경로

저장은 transaction, 알림은 commit 뒤입니다. 계약·schema·웹 응답을 함께 바꾸면 각 경계를 확인합니다.
사용자 HTTP 경로는 입력 검사(app.ts `parseInput`, 422) → db 저장 함수(`Stored`: 값 + commit 뒤 할 일, 또는 거부 이유) → [server/after-commit.ts](../../../apps/server/src/after-commit.ts) `completeStored` → app.ts `respond`(거부는 problems.ts `ownerRefusalResponses`) 순서입니다. commit 뒤 할 일은 Event·전역 설정 변경 신호(`settings_changed`) 알리기 → 취소 → 재개한 조직의 대기 깨우기(기다림) → 깨운 에이전트 촉진 → 자리가 늘어난 프로바이더 연결을 기다리는 에이전트 촉진 순서로 `applyAfterCommit`이 하며, 조직 도구 쪽(tools.ts `respondWrite`의 저장·`tool.refused` 거부, 도구 검사 거부, 읽기 도구 기록)과 heartbeat 확인도 같은 함수를 씁니다([단위](../../../apps/server/src/after-commit.test.ts)). server에서 이 함수와 dispatcher 밖의 직접 `hub.publish`·`dispatcher.kick`류 호출은 lint가 막습니다([eslint.config.js](../../../eslint.config.js)). 각 절 파일의 연결 경로에 나오는 `EventHub → kick`은 이 단계입니다.
