# 근거 규칙

모든 주장은 Evidence ID(`E01`…)로 원본에 연결한다. 기존 `docs/research/` 문서의 ID는 새 E로 옮기지 않고 그
문서의 anchor 링크로 인용한다.

| 수준 | 뜻 |
|---|---|
| 실행 확인 | 이번 조사에서 직접 실행·조작한 동작. 명령·버전·결과 요지를 남긴다 |
| 소스 확인 | 고정 SHA의 파일·심볼·줄 범위를 직접 읽은 사실. 코드가 그렇게 쓰여 있다는 뜻이다 |
| 문서 주장 | 공식 문서·README·명세·논문·issue가 말하는 내용 |
| 추론 | 위 근거에서 끌어낸 판단. 출처 E를 적는다 |
| 미확인 | 접근 불가·실행 실패·범위 밖. 이유를 적는다 |

- GitHub 소스는 `https://github.com/<owner>/<repo>/blob/<40자 SHA>/<path>#L<a>-L<b>`와 함수·테스트 이름으로
  적는다. 브랜치 이름이 든 URL은 근거로 쓰지 않는다.
- 소스 확인과 실행 확인을 구분한다. 테스트도 읽은 것과 실행한 것을 나눈다.
- 찾지 못한 기능은 「조사 범위(<읽은 경로·문서>)에서 확인하지 못함」으로 쓴다. 「지원하지 않음」은 문서의
  명시나 거부 분기 같은 부재의 근거가 있을 때만 쓴다.
- 기존 고정 SHA 근거를 재사용하면 파일마다 두 ref의 blob SHA를 비교한다(compare API의 파일 목록은 300개에서
  잘린다). 「변경 없음 / 변경됨: <요지> / 미확인」을 적고, 결정에 닿는 변경이면 새 SHA로 다시 읽는다.

  ```bash
  gh api 'repos/<owner>/<repo>/contents/<path>?ref=<sha>' --jq .sha
  ```

- worker 보고는 후보와 위치를 알려 줄 뿐이다. 결정 표에 쓰는 근거는 메인이 원문을 다시 열고,
  `.reference-cache/<key>/main-verification.md`에 일치·정정 결과를 남긴다.
- 코드 재사용을 권고하면 그 SHA의 LICENSE, 파일 header, NOTICE, 함께 들어오는 의존성을 확인한다. 설계
  참고뿐이면 그렇다고 적는다.
